Architecture

Memory grounded in session evidence.

ShellBrain turns completed work into durable memory, then returns the small amount of context an agent needs.

Memory flow

Each layer links to its evidence.

session transcript
  -> episodes      # what happened
    -> memories    # what was learned
      -> concepts  # how it's organized
        -> recall  # what's retrieved

Concepts link to memories. Memories link to episode events. Episode events preserve the session trail.

Evidence

Unsupported memories are skipped.

Every durable memory links to the exact episode event that supports it. ShellBrain skips a write when the evidence is ambiguous.

Memory that cannot justify itself should not persist.

Stored knowledge

What ShellBrain remembers.

Problems and attempts

A case begins with a problem. Solutions and failed tactics link back to that problem.

Facts, preferences, and changes

When a fact changes, ShellBrain keeps the old fact, records the change, and links it to the new fact.

old fact->change->new fact

Concepts

Concepts connect reusable ideas to concrete memories. The memories remain the source of evidence.

Episodes

Episodes preserve prompts, agent steps, tool calls, and outputs from each session.

active maybe_stale stale superseded wrong archived
Recall

Search, expand, summarize.

01

Search

BM25 finds matching terms. Semantic search finds similar meaning. ShellBrain merges the ranked results.

02

Expand

ShellBrain follows graph links and nearby semantic matches to find related memories.

03

Summarize

The recall agent removes duplicates, weighs what is current, and returns a compact brief.

Inner agents

The working agent stays focused.

The working agent calls recall, receives a brief, and continues its task.

A knowledge builder turns session evidence into memories. A recall agent searches those memories and returns useful context.

Storage

Your knowledge stays yours.

The embedding model runs locally. ShellBrain sends no outbound telemetry.

Store data in the managed local PostgreSQL and pgvector runtime or in your own PostgreSQL database with pgvector.
